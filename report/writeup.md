# MorphBPE for Polysynthetic Low-Resource Languages: Cree, Inuktitut, and Guarani

## 1. Setup

- **Cree**: `KonradBRG/plains-cree-figurative` (HF Hub, gold + silver splits) -- a figurative-language *classification* dataset, so only the `text_cree` column is used, labels dropped. Checked: neither split contains Ojibwe-sourced rows (unlike the sibling FNLP project's own parquet, which mixes some in for an unrelated cross-lingual pretraining objective), so no source filtering was needed. 17,707 word types / 9,762 train sentences after tokenization and a 90/5/5 split.
- **Inuktitut**: `EdinburghNLP/nunavut-hansard-plusplus`, roman-transliteration subset, subsampled to 150,000 sentences (seed 0). 423,450 word types / 135,000 train sentences, same split convention.
- **Guarani**: the Jojajovai Guarani-Spanish parallel corpus (Chiruzzo et al., LREC 2022), pulled directly from its GitHub repo. Only the Guarani column is used; unlike Cree/Inuktitut, this corpus ships its own fixed train/dev/test split (a `split` column), which is used as-is rather than re-splitting, since that's what the corpus's own benchmark paper reports numbers against. 46,754 word types / 20,106 train sentences.
- **All three data sources are pinned to a specific revision/commit**, not a moving branch head -- found necessary the hard way: an early Cree run and a later one produced different word-type counts (18,621 vs. 17,707) because the underlying HF dataset had been updated in between. `src/fetch_data.py` now pins exact commit SHAs for all three sources, so re-fetching always reproduces the same corpus.
- **Tokenization**: whitespace-split, leading/trailing punctuation stripped unconditionally, including hyphens (a medial hyphen, e.g. Cree preverb-stem boundaries like `kî-kitimâkisiwak`, is never at a token's edge, so it survives regardless), tokens with no actual letter dropped (Hansard budget figures like `-$1,120,000`, or an isolated dash, are not words). A small residual (~0.4-0.8% of types) of noisier tokens remain -- OCR artifacts in the historical Bloomfield Cree source, slash-joined alternatives and similar Hansard transcription conventions in Inuktitut -- documented here rather than further special-cased.
- **Boundary sources**: Morfessor 2.0 for all three languages, plus a rule-based analyzer for each -- `giellalt/lang-crk` (FST) for Cree, the Uqailaut NRC analyzer for Inuktitut, `apertium/apertium-grn` for Guarani -- used as the primary/more-defensible reference where it covers a word, falling back to Morfessor otherwise. See Section 2.
- **Tokenizers**: both a from-scratch character-level BPE baseline and a boundary-constrained "MorphBPE" following Algorithm 1 (pre-segment training words at boundary-lexicon morphs, then run the identical merge-learning loop with cross-boundary merges excluded from consideration). Applying a learned merge list needs no boundary info -- a merge that would have crossed a boundary was simply never learned -- so both variants share one apply-time code path.
- **Vocab-size selection**: rather than a fixed, arbitrarily-chosen merge count, MorphBPE is trained once to a generous ceiling (1,000 for Cree, 8,000 for Inuktitut, 3,000 for Guarani), checkpointed at regular intervals along that single merge list, and evaluated by mean Morph Edit Distance on the **dev** split at each checkpoint length. The length minimizing dev distance is selected and applied to *both* tokenizers, so they're compared at one matched, data-justified vocabulary size rather than an arbitrary fixed one.
- **Metrics**: Fertility (mean subwords/word), Consistency F1 (boundary-position precision/recall/F1 against the reference lexicon), Morph Edit Distance (sequence-level Levenshtein distance against the reference lexicon, normalized to [0,1]), and LM Cross-Entropy Loss. All three languages use a randomly-initialized GPT-NeoX transformer matching (a scaled variant of) the Pythia-14M architecture's hyperparameters, vocabulary resized to each tokenizer's own vocabulary -- see Section 4 for why Cree and Guarani use a smaller, depth-halved variant than Inuktitut. None of this replicates the source paper's actual protocol (300M/1B-parameter decoders on ~6B/~20B tokens), which doesn't scale down to corpora this size.

## 2. Boundary source outcomes

- **Cree (`lang-crk`)**: composing the strict analyzer with the "generator-with-morpheme-boundaries" transducer (after `remove_optimization()`, since the prebuilt release ships optimized-lookup-format transducers that don't support `compose()` directly, despite HFST's own documentation claiming that type "cannot be converted to any other type") gives a coarse but linguistically real prefix|stem|suffix split -- only the stem's left/right edges are marked, not a full multi-morph decomposition. **Coverage: 36.6% of Cree word types** (6,480/17,707). Spot-checking ~20 segmentations by hand showed plausible, real preverb/stem/suffix splits (e.g. `kâ-pakastawêhomiht` → `kâ- pakastawêh omiht`, `ê-kî-isi-pêyakoyân` → `ê- kî- isi- pêyako yân`).
- **Inuktitut (Uqailaut)**: its native decomposition format (`{surface:id}` per morph) gives genuine multi-morph segmentation with no alignment ambiguity. Getting it running at corpus scale surfaced a real, instructive debugging story:
  - A JVM-per-word approach would take ~26h for the vocabulary size involved; the linguistic-database load costs ~2s per process spawn, so a single long-lived subprocess batching many words is necessary.
  - An early hardened version (persistent subprocess, sentinel-filtered stdout, per-word timeout with automatic restart, frequency capping, randomized order, a wall-clock ceiling) still appeared to stall on **essentially every word attempted** -- which looked like a fundamental tool limitation until a direct question ("is this integrated correctly? Uqailaut should get >90% coverage on Hansard text") prompted re-verification. Testing the exact same "stalled" words through the most minimal possible path (a raw CLI call, bypassing all Python orchestration) showed they decomposed instantly and correctly -- the analyzer was never the problem.
  - Two real bugs in the Python wrapper were the actual cause: (1) `for line in stdout:` on a subprocess pipe silently read-ahead-buffers internally (an idiom tuned for reading whole files, not streaming from a live process), so already-computed result lines sat unseen while every per-word timeout below fired; (2) after fixing that, results came back fast but were silently discarded, because the JVM's stdout wrapped the result sentinel in stray `\x01` bytes (some internal PrintStream/encoder artifact) that broke the prefix match. Fixing both (see `src/fst_boundaries_iku.py`'s module docstring) took throughput from ~0 to 100+ words/sec.
  - **Coverage after the fix: 79.6% of the 15,000 most frequent word types** (11,937/15,000) -- the cap this project's results use. A follow-up run without that cap, attempting the full ~410k-word vocabulary, was tried but hit its (90-minute) time budget having only reached the top ~21.7k most-frequent words, with a *worse* within-scope coverage rate (67.5%) than the smaller, faster-completing cap -- throughput degrades substantially on rarer, longer wordforms, so a larger nominal cap doesn't reliably buy more coverage in practice. The smaller cap was kept.
- **Guarani (`apertium-grn`)**: this Apertium module ships no prebuilt binaries and its usual build needs a heavy native toolchain (lttoolbox, Apertium core, HFST's command-line tools, VISLCG3) that isn't packaged for macOS. A from-scratch Python-only replication of its build graph (using the pip `hfst` package's own compile/compose primitives, skipping the native toolchain entirely) compiled fast but produced a transducer with genuine cyclic, infinitely-ambiguous analyses for ordinary words -- a real correctness gap, not a performance one. Building the actual native toolchain (MacPorts for lttoolbox/Apertium-core/VISLCG3, HFST compiled from source) and applying one small source patch (a modern-`hfst-lexc`-vs-2021-era-lexc-file Unicode incompatibility) produced a correct transducer with no such cycles. The compiled result is committed as a pre-built artifact (`tools/apertium-grn/grn.seg.hfst`, see `tools/apertium-grn/BUILD.md`), so no downstream run needs the native toolchain. **Coverage: 8.1% of Guarani word types** (3,793/46,754) -- much lower than the other two languages' analyzers, reflecting both a comparatively small dictionary (apertium-grn's own test fixtures report ~86% coverage, but on a short, formal reference text, not this corpus's heavily code-mixed news/blog/social-media register) and the corpus's substantial Jopara (Guarani-Spanish code-mixing) content.
- **Morfessor spot-check**: ~20 hand-reviewed segmentations per language against known morphology.
  - *Cree*: plausible splits for many words (e.g. `sipwêhtahik` → `sipwêhtah ik`), but a meaningful fraction of rarer types come back completely unsegmented -- consistent with the corpus-size caveat below.
  - *Inuktitut*: plausible root+suffix-chain splits for the large majority reviewed (e.g. `uqaalautiqaqtuinnaujunnangimmata` → `uqaalauti qa qtuinnau junnangimmata`), consistent with its much larger, better-resourced training corpus giving Morfessor a stronger statistical signal than Cree's.
  - *Guarani*: plausible splits for common inflected verb forms (Guarani's verb morphology is agglutinative and fairly regular), though -- like Cree -- rarer types and Spanish-loanword forms (Jopara) often come back unsegmented.

## 3. Results

| Language  | Tokenizer | Vocab size | Fertility | Consistency F1 | Morph Edit Distance | LM Test Cross-Entropy |
|-----------|-----------|------------|-----------|-----------------|----------------------|-------------------------|
| Cree      | BPE       | 1000       | 2.352     | 0.266           | 0.470                | 2.972                   |
| Cree      | MorphBPE  | 1000       | 2.599     | 0.472           | 0.324                | 2.743                   |
| Inuktitut | BPE       | 8000       | 2.189     | 0.282           | 0.634                | 3.851                   |
| Inuktitut | MorphBPE  | 8000       | 2.469     | 0.556           | 0.392                | 3.572                   |
| Guarani   | BPE       | 3000       | 2.050     | 0.106           | 0.471                | 2.971                   |
| Guarani   | MorphBPE  | 3000       | 2.104     | 0.237           | 0.406                | 2.904                   |

*(All three languages' vocab-size sweeps selected the full merge-count ceiling -- dev Morph Edit Distance was still improving at that point in every case, so a higher ceiling might improve results further; not pursued given the retraining cost this late in the project. Full per-checkpoint sweep values and `n_scored_words`/`n_test_words` denominators -- Cree 3,185/3,907; Inuktitut 46,698/66,230; Guarani 63,136/71,367 -- are in `results/{lang}_results.json`.)*

**Cree interpretation**: MorphBPE clearly wins on both morphology-based metrics -- Consistency F1 nearly doubles (0.266 → 0.472) and Morph Edit Distance drops by roughly a third (0.470 → 0.324) -- and also achieves lower LM cross-entropy (2.972 → 2.743). The cost is fertility: MorphBPE produces *more* subwords per word (2.599 vs. 2.352), because it's forbidden from making certain merges plain BPE would happily make even when they cross a real morpheme boundary.

**Inuktitut interpretation**: the same pattern holds, with a *larger* effect size on both morphology metrics. Consistency F1 nearly doubles again (0.282 → 0.556), Morph Edit Distance drops by more than a third (0.634 → 0.392, a bigger relative improvement than Cree's), and LM cross-entropy drops from 3.851 to 3.572. That the morphology-metric effect is if anything stronger on Inuktitut -- despite its reference lexicon being a mix of a genuinely rule-grounded analyzer (79.6% of the most frequent types) and Morfessor fallback, versus Cree's fully rule-grounded-where-covered FST -- is a reassuring sign the result isn't an artifact of one particular reference source.

**Guarani interpretation**: the same direction holds a third time, though the effect sizes and absolute levels differ. Consistency F1 more than doubles (0.106 → 0.237) and Morph Edit Distance drops modestly (0.471 → 0.406), with lower LM cross-entropy (2.971 → 2.904). Both Guarani's absolute Consistency F1 values are much lower than Cree's/Inuktitut's, and fertility barely rises (2.050 → 2.104, the smallest gap of the three languages) -- plausibly because Guarani's reference lexicon is overwhelmingly Morfessor-driven (apertium-grn covers only 8.1% of word types, vs. 36.6%/79.6% for Cree/Inuktitut), so the "ground truth" MorphBPE is being measured against is itself less reliably rule-grounded here than in the other two languages (see Limitations).

**Overall**: constraining BPE merges to respect morphology costs some compression (higher fertility) but consistently buys a segmentation that is both more linguistically faithful (higher Consistency F1, lower Morph Edit Distance) and, on this small-scale diagnostic, more learnable (lower LM cross-entropy) -- in all three languages, at three different corpus scales, under two different boundary-source coverage regimes, and (per Section 4) two different LM architecture scales.

## 4. Limitations

- **Cree corpus size**: 9,762 training sentences (17,707 word types) is small enough that Morfessor's MDL-based induction is expected to be noisy -- many rare types come back unsegmented. Mitigated, but not eliminated, by the independent FST cross-check (36.6% coverage).
- **Inuktitut subsample**: 150,000 of 664,257 available sentences (not the full corpus), for tractable Morfessor/BPE training and iteration speed.
- **Guarani is agglutinative, not typically classified as polysynthetic** -- included alongside Cree and Inuktitut because it shares some of the same morphologically-rich properties this project is interested in (polypersonal verb agreement, some noun incorporation), and because a real, if imperfect, rule-based analyzer (`apertium-grn`) exists for it, but it is typologically a different (less extreme) case than the other two languages, worth keeping in mind when comparing effect sizes across all three.
- **Asymmetric boundary-source coverage/granularity**: Cree's FST source gives a coarse stem-edge split at 36.6% coverage; Inuktitut's Uqailaut source gives a finer multi-morph split at 79.6% coverage (of the top 15,000 word types); Guarani's apertium-grn source gives a finer multi-morph split too, but at only 8.1% coverage. All three fall back to Morfessor for uncovered words. Consistency F1 and Morph Edit Distance are restricted to test words present in the reference lexicon in every case (`n_scored_words`/`n_test_words` in the results JSON), but the three languages' morphology-based metrics rest on qualitatively different kinds of reference (coarse-but-rule-grounded, finer-but-partially-rule-grounded, and mostly-Morfessor-driven respectively) -- worth keeping in mind when comparing effect sizes directly across languages, and the likely explanation for Guarani's comparatively muted fertility/Consistency-F1 gap noted above.
- **LM architecture is asymmetric by corpus scale, and doesn't replicate the source paper's protocol**: the MorphBPE paper trains 300M/1B-parameter decoders (LLaMA-Factory) on ≈6B/≈20B tokens -- 4-6 orders of magnitude more data than this project's corpora. That protocol does not scale down to this data. All three languages use a randomly-initialized GPT-NeoX transformer, but at two different scales: Inuktitut uses the real, unmodified Pythia-14M hyperparameters (~3.1M total parameters with its own vocabulary); Cree and Guarani use a depth-halved variant (3 layers instead of 6, ~1.3M-1.4M total parameters) -- not an official Pythia size, chosen because with these two languages' much smaller, tinier-vocabulary corpora, matching Pythia-14M's literal backbone size would give a *worse* tokens/parameter ratio than the already-poor one Inuktitut has, the opposite of the right direction for a smaller corpus. Resulting tokens/parameter ratios (all far below the Chinchilla-style 20:1 reference point): Cree ~0.29-0.31, Guarani ~0.69-0.72, Inuktitut ~1.24-1.37. Pythia's *pretrained* weights were never an option regardless of corpus size: its fixed English GPT-NeoX-20B BPE vocabulary has no correspondence to this project's own from-scratch tokenizer vocabularies, which token segmentation is easier for an LM to learn from is exactly the variable under study, so reusing English-token embeddings would inject a confound rather than remove one. Because Cree/Guarani and Inuktitut use different-scale models, only the *within-language* BPE-vs-MorphBPE comparison is meaningful for each; raw cross-entropy values are not directly comparable *between* Inuktitut and the other two.
- **Guarani's boundary lexicon has a small, expected cross-machine variance source**: `apertium-grn`'s lookup uses a wall-clock time budget (2s/word) to guard against the lexicon's recursive paradigms (see above) enumerating indefinitely; on a faster or slower CPU, that same window can explore a different amount of the search space for an ambiguous word, occasionally changing which analysis is returned first. Observed effect: re-running the full pipeline on different hardware selected a MorphBPE vocabulary differing by exactly one merge (2,852 vs. 2,853), with correspondingly tiny (<0.02) shifts in the affected metrics -- the qualitative story is unaffected. Inuktitut's Uqailaut source has the same kind of wall-clock-bounded lookup and could show the same small effect in principle; Cree's FST lookup has no such bound and reproduced identically across machines.
- **LM results are single-run point estimates**, though now fully seeded (`torch.manual_seed(0)`, plus `torch.cuda.manual_seed_all(0)` when training on GPU) for exact reproducibility given identical inputs -- the residual variance described immediately above (from the boundary lexicon, not the LM training itself) is the only known source of run-to-run difference remaining.
- **Residual corpus noise**: ~0.4-0.8% of word types are OCR artifacts (Cree) or Hansard-specific transcription conventions (Inuktitut) that were not further cleaned.
